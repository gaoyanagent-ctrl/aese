# Enterprise Genesis 游戏交互一致性与无死路规范

## 1. 目的

本规范把 M9 已验证的经营游戏交互提升为 M10–M24 的项目级约束。AESE 是 IAOS 的智能企业运行仿真环境；玩家应当作出经营判断，而不是替 World、Agent 或 IAOS 填写系统字段、证据编号和技术 JSON。

标准任务循环只有一条：

```text
IAOS 权威状态派生当前事件
-> 场景中的当前 NPC 给出一个经营任务
-> Agent 或 World 准备草案/事实
-> 玩家选择、少量调整或确认
-> AESE Command Gateway 提交 IAOS Capability
-> IAOS 事务、审批、审计与 Outbox 落地
-> 投影刷新并自动引导到唯一下一任务
```

## 2. 信息所有权

| 信息 | 负责产生 | 玩家动作 |
| --- | --- | --- |
| 经营意图、取舍、金额上限、目标日期 | Human，可接受 Agent 建议 | 选择、调整、确认 |
| 候选方案、估算、WBS 草案、风险解释 | Agent | 采纳、修订、拒绝；不能由 Agent 自批 |
| 报价、权属、交付、施工和验收事实 | World 外部参与者/仿真引擎 | 发起、接收、确认；不得手填证据 |
| 主数据、资金、预算、流程状态、审批结果 | IAOS | 只读审阅并通过 Capability 发出命令 |
| ID、correlation、idempotency、证据引用、发生时间 | 服务端 | 页面不得要求玩家输入 |

## 3. 玩家输入预算

1. 默认任务不得出现 JSON、数据库 ID、证据引用、外部参与者 ID、系统状态值或哈希输入。
2. 一个主线任务在展开专家设置前，最多要求三项真正影响经营结果的决定。
3. 金额和日期只有在属于人员授权边界时才允许修改；必须从权威事实或 Agent 草案预填，不能写死为某一家公司的固定数值。
4. 技术参数由 Agent 草拟并提供“为什么”；默认展示摘要，专业用户可通过“查看/调整专业参数”渐进展开。
5. 业务理由优先使用可理解的原因选项；只有例外、驳回或高风险决定才要求补充文字。
6. “人工接管”保留完整专业表单，但必须是次级入口并明确其责任、校验和审计后果。

## 4. 场景与档案

- 主画面占满可用视口；业务表单只在当前 NPC 的临时任务对话框中出现。
- 场景只展示当前事件、地点、人物和可检查物件。完成事实进入相应地点档案，不常驻为长表单或流水列表。
- 每一时刻只突出一个主动作。次级动作不得与主线按钮竞争视觉优先级。
- 玩家完成动作后，界面必须自动刷新、关闭或切换当前任务，并明确下一地点、NPC 和动作。
- 控件最小可点击区域 44×44 px，支持键盘操作、可见焦点、错误就地解释和异步状态。

## 5. 无死路不变量

1. 每个非终态 committed 状态必须恰好存在一个可达主动作。
2. UI 不得为尚无已发布 Capability/Process Artifact 的节点创建可点击 NPC、按钮或“下一步”承诺。
3. 若后续纵切尚未交付，当前里程碑必须显示为明确的章节完成边界，并允许返回档案；不得伪装成可继续任务。
4. Capability 成功后必须由权威投影派生下一状态，不得依赖本地计数、固定剧情帧或手工刷新。
5. 页面恢复、重放和重复点击必须回到同一任务状态，不得创建重复业务事实。

## 6. 发布门禁

任何新主线节点在进入玩家路由前必须同时具备：机器可读输入/输出合同和中文解释；已发布 Effective Capability Artifact；需要多步协作时具备已发布 Effective Process Artifact；Human/Agent/World/IAOS 所有权边界；权威 Entity 或只读 projection 与档案入口；成功、拒绝、重试、恢复和幂等测试；前后节点 UI 端到端测试；System Atlas、设计、运行手册和进展声明。

组件测试至少断言：当前任务只有一个主 CTA；业务输入不在关闭的任务弹窗中；World 确认请求不接受浏览器提供的证据字段；非终态不存在无动作页面。

## 7. M10 适用修订

- 首次设施需求改为“Agent 准备 2–3 个需求草案 → 玩家选择 → 仅调整投资上限/目标日期等真实管理边界 → 确认”。面积、电力、候选数量和方案范围放入可展开专业参数。
- 外部场址调研改为“发起调研 → 园区 World 引擎形成权属、报价、面积、电力、日期、许可和证据 → 玩家查看并确认接收”，玩家不再填写 Observation。
- 场地交付完成后，在设施项目/WBS Capability 尚未发布前显示“场址取得章节完成”，不得提供虚假的“准备设施项目”动作；Capability 发布后再由权威状态解锁下一 NPC。
- 项目/WBS 继续采用 Agent 生成草案、项目负责人调整并提交审批、受派审批人在 AESE 治理会议决定、IAOS 激活基线的协作闭环。

## 8. 与其他设计的关系

- DES-028 定义游戏体验与 M9 基线；本规范把其交互约束推广到所有后续章节。
- DES-011 定义 M10 领域对象和业务闭环；本规范约束其玩家呈现与交互责任。
- ADR-004 约束 World 事实所有权；外部事实不能降级为浏览器表单输入。
- ADR-005 约束流程运行事实源；未发布的流程不能以剧情按钮替代。
