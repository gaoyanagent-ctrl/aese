# 财务治理、审批、职责分离与 Agent

## 1. 目的

定义财务岗位、授权、审批、Capability、Agent Tool、事件和 UI 的共同控制面。执行者、
责任岗位、审批人和数据所有者必须分开表达，不能用一个 `participant` 字符串替代。

## 2. 财务组织与岗位

最小岗位：

- CFO / 财务负责人
- Controller / 财务经理
- 总账会计
- 应付会计
- 应收会计
- 资金出纳
- 成本会计
- 资产会计
- FP&A
- 内部审计

财务共享中心可以承接多个法人的任务，但每个工作项仍保存客户法人、责任岗位、服务组织、
实际执行人和 Mandate。岗位空缺时升级，不伪造任职。

## 3. 关键职责分离

禁止或需要增强审批的组合：

- 供应商银行账户维护 + 付款释放；
- 采购/收货 + 供应商发票审批；
- 客户信用维护 + 坏账核销；
- 手工凭证制单 + 同凭证审批/过账；
- 银行流水导入 + 对账差异核销；
- 资产验收 + 转固/处置批准；
- 标准成本维护 + 发布；
- 预算编制 + 最终批准；
- 关账执行 + 重开批准；
- 报表生成 + 法定发布。

SoD 冲突在 assignment、Mandate、审批路由和 Capability 执行前均失败关闭。

## 4. 审批模型

审批路由支持：

- 角色、具体人员、申请人上级、责任岗位、数据 Steward；
- 金额、币种、法人、BU、项目、风险、异常类型；
- 串行、并行、会签、或签、多层级和升级；
- 回避申请人/制单人、自批阻断、代理和超时；
- 审批版本、意见、附件、决定、有效期和消费状态。

典型审批：供应商/银行信息变更、重大付款、手工凭证、预算与修订、标准成本发布、资产处置、
坏账核销、期间重开和报表发布。

## 5. Capability 与写入边界

持久业务变化必须经过已发布且有 active implementation binding 的 Capability，并携带
`capability_execution`。HTTP、Process、Agent、事件消费者和定时任务不能直接调用内部
mutation 或 DML。

每项能力说明：

- 业务目的和非目标；
- 输入/输出业务表单；
- 读取/写入 Entity；
- Policy、Approval、Process、Agent、Event；
- 幂等、失败补偿、证据和恢复；
- UI 配置/运行入口。

## 6. Agent

Agent 通过受治理 Tool Registry 工作：

- 财务 Agent：草拟账套、科目、凭证和预算；
- AP/AR Agent：建议匹配、付款/催收优先级；
- 成本 Agent：解释标准/实际成本和差异；
- 资金 Agent：现金预测和银行对账建议；
- 审计 Agent：SoD、异常、凭证和关账检查；
- FP&A Agent：预算、预测和经营分析。

默认只建议或生成草稿。重大付款、过账例外、成本发布、关账、重开和报表发布必须由授权
主体批准。外部 LLM 未启用时可使用确定性规则 runtime，但 UI 必须明确标识。

## 7. 菜单与解释入口

目标菜单：

- 财务工作台
- 总账与凭证
- 应收管理
- 应付管理
- 资金与银行
- 固定资产
- 存货与成本
- 预算与预测
- 结账中心
- 财务报表
- 管理驾驶舱
- 财务基础设置

每个页面提供“功能说明”，说明目的、角色、前置配置、步骤、上下游关系、校验、恢复和
权威设计。业务单据、凭证、余额、报表和 KPI 提供双向穿透。

## 8. 数据与安全

- 全部交易表 FORCE RLS；
- 数据访问同时考虑 tenant、法人、BU、Data Set、敏感字段和职责；
- 金额使用最小货币单位，汇率使用高精度 decimal；
- 银行账户、身份证明、工资和信用属于敏感数据；
- 导入默认 dry-run，付款、过账、关账要求显式 apply；
- 重复、乱序、迟到、重启和失败后无部分写入；
- Agent 与人使用相同权限、RLS、Policy 和审批边界。

## 9. 验收

- 任何执行可回答“谁以什么岗位/授权，为哪个法人执行了什么能力”；
- 自批、职责冲突、越权金额和无 binding 写入失败关闭；
- 审批人由配置解析而非硬编码；
- 通知、待办、审批对象、业务内容和证据可见；
- 用户不读 DSL/JSON/源码也能理解配置和操作；
- Agent 输入、输出、工具调用、审批和落库结果可穿透。
